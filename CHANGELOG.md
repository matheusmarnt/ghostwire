# Changelog

All notable changes to this project will be documented in this file.

The format is based on [Keep a Changelog](https://keepachangelog.com/en/1.0.0/),
and this project adheres to [Semantic Versioning](https://semver.org/spec/v2.0.0.html) strictly from v1.0.0 onward (SPEC-PKG-11).

## [Unreleased]

### Added

- Repository foundation — composer.json, governance docs, CI workflows (M0).
- Dual Livewire 3.6+/4.x bridge selected by runtime feature detection (SPEC-INT-20).
- Ghost Layer portal, state machine (idle/pending/visible/settling), and `freeze` mode.
- `wire:ghost` directive with `.freeze`, `.off`, `.ignore`, `.keep`, `.delay.<n>ms`, `.hold.<n>ms`, `.rows.<n>` modifiers.
- Morph safety: Ghost Layer mounts to `document.body`, outside any component's reconciled tree. Guarded by dual `morph.updating` and `morph.removing` skip() handlers (SPEC-MORPH-01..06).
- Freeze hold enforcement: `Livewire.hook('morphed')` reapplies `gw-frozen` class during hold window, preventing Livewire's attribute diffing from stripping it prematurely (SPEC-TIME-02).
- Silence-by-default: Livewire 3 polling detection via `wire:poll` heuristic (DOM shape recognition), Livewire 4 keystroke sync via `wire:model.live` action shape recognition, and v4 `wire:poll` action detection prevent false-positive activations (SPEC-API-20/21).
- Real skeleton synthesis (`synthesize` mode, the `wire:ghost` default): a host's DOM subtree is walked, classified into Bone Types (text/heading/media/avatar/icon/control/container), batch-measured with reads/writes strictly separated, and emitted as a Bone Tree positioned in host-relative coordinates — replacing M1's empty portal with real skeleton bones (SPEC-SYN-01/10/12/16/17, SPEC-RND-01/02). Nested `wire:ghost` hosts (any modifier) are walk boundaries. Non-axis-aligned hosts/descendants (rotation/skew, conservatively including `matrix3d` and unrecognized transforms) degrade the affected bone, or the whole host to `freeze`, rather than rendering a misplaced bone (SPEC-SYN-16). An empty host degrades to `freeze` unless `.rows.<n>` supplies a placeholder-row hint (SPEC-SYN-17).
- Bone rendering: `renderBones()` paints the Bone Tree into the existing Ghost Layer portal, replicating the host's own border-radius and overflow-clipping once at mount time (SPEC-RND-02).
- Host concealment (SPEC-MORPH-03): while bones are shown in `synthesize` mode, the host's own content is now actually hidden and non-interactive (`visibility: hidden; pointer-events: none` via `.gw-concealed`) instead of staying visible/clickable underneath the bones — `freeze` mode is unaffected and keeps its own dimming via `.gw-frozen`. `.keep`-marked hosts get an unconditional `.gw-kept` override (`visibility: visible; pointer-events: auto`) applied at attach time, so a kept host stays visible/interactive even nested inside a concealed ancestor.
- Signature-based memoization (SPEC-SYN-20/21): a Bone Tree is cached per host, keyed by a structural signature (tagName/BoneType/className/depth — never text content), and invalidated by a `ResizeObserver` once the host's width drifts ≥4px (comparing border-box to border-box, avoiding a permanent content-box/border-box mismatch). An invalidated, currently-visible skeleton is now actually re-synthesized and repainted in place (or degraded to `freeze` if it no longer has content) instead of drifting out of sync until the next show cycle.
- Geometry + zero-CLS Definition-of-Done test suite (Pest 4 + Playwright) covering the three gallery layouts (paginated table, grouped table, card grid): every rendered bone is independently verified to overlap its real source element within a 2px tolerance, and triggering a skeleton introduces zero Cumulative Layout Shift.
- Browser test suite (Pest 4 + Playwright) covering morph safety, freeze timing, silence behavior, synthesis geometry, and host concealment, run against both Livewire versions in CI.
- Repeat-sibling sampling (SPEC-SYN-11): a run of ≥3 structurally-uniform siblings (same tag, class, and direct-child count, with heights within a small tolerance) samples only the first 3 (configurable), then clones the sampled template's bones for the remaining real siblings — preserving the real item count and real measured spacing (via pitch between sampled siblings) without walking or measuring every item. Text bones specifically are never geometrically cloned: each unsampled sibling's own text content is measured directly (a shallow, non-recursive scan), so real per-row text width is preserved exactly, not approximated from the template.
- Depth/candidate-count-limit degradation (SPEC-SYN-13): exceeding the depth cap (12) or the candidate-count cap (300) now degrades to one aggregated `block` bone standing in for whatever wasn't individually walked, instead of silently dropping that content — a host never ends up with a gap or with zero skeleton because it was too large or too deep.
- Scrollable-container clipping (SPEC-SYN-14): a candidate behind a scrollable (or otherwise `overflow`-clipping) ancestor is excluded once it falls outside that ancestor's own visible box, computed by walking the ancestor chain and intersecting each clipping ancestor's rect into the host's.
- Sticky/fixed viewport geometry (SPEC-SYN-15): bones for `position: sticky`/`fixed` elements already reflect their live, pinned viewport position (via `getBoundingClientRect()`), verified against a fixture where a sticky header's static and pinned positions genuinely diverge after scrolling.
- Adaptive freeze (SPEC-PERF-07): a host whose synthesis is measurably slow two cycles in a row degrades to `freeze` instead of repeating the expensive work; a single slow sample (ordinary GC/engine jitter) does not trigger it, and any fast synthesis resets the streak.
- Performance gates (SPEC-PERF-01/02/03/04/10): a Vitest regression guard proves the walk→measure→emit pipeline and the renderer never read layout after writing to the DOM; a browser test proves synthesis time scales sub-quadratically with node count (100/200/400/800-node fixtures, ratio below 2.5 between consecutive sizes, bounded in practice by the 300-candidate cap); a browser test proves no measured `synthesize()` call exceeds 50ms; the zero-CLS gate is extended to the three new M3 gallery layouts.
- Three new private test-gallery fixtures: a uniform repeated list (repeat-sampling), a scrollable column with a sticky header (scroll clipping + sticky geometry), and a parametrized node-count layout with deliberately non-repeat-eligible markup (raw complexity measurement).
- `#[Ghost]` PHP attribute (`class` target — see Scope below for `method`), resolved by a `ConfigResolver` precedence cascade across the class-attribute, inherited base-class/trait-attribute, `config/ghostwire.php`, and package-default levels, for all nine fields (`mode`, `only`, `except`, `delay`, `hold`, `rows`, `poll`, `sync`, `lazy`) — field by field, so declaring one field never discards an inherited value for another (SPEC-API-10/11). `only`/`except` mutual exclusion is validated eagerly, with an explanatory exception, the first time a class's config is resolved (SPEC-API-23).
- `Ghostwire\Livewire\GhostComponentHook`, a real Livewire package hook (registered on both Livewire 3.6+ and 4.x, confirmed against the actual installed vendor source rather than assumed from documentation — pendency A9) that serializes the resolved config as a compact-key `data-ghost` attribute on every component's root element, hardened per SPEC-SEC-01 (Livewire's own attribute-escaping path, never manual string concatenation) — SPEC-API-30/31.
- JS-side `data-ghost` parsing: a closed-schema validator discards the whole payload on any unknown key or wrong-typed value (SPEC-SEC-02), with numeric/array fields clamped (`delay`/`hold` 0–60000ms, `rows` 0–1000, action names ≤64 chars matching `[A-Za-z0-9_]`) per SPEC-SEC-03. With no `wire:ghost` directive anywhere in the component, `#[Ghost]` on the class now auto-attaches the component root as the sole host (SPEC-API-12); with `wire:ghost` present anywhere in the component (root or a descendant), the attribute only supplies policy/defaults to the existing host(s), never a second one (SPEC-API-13).
- Full directive⊕attribute precedence merge (SPEC-API-40): a `wire:ghost` modifier only overrides the fields it explicitly sets, never discarding an attribute-level field it didn't mention. `mode: 'off'` is terminal at every level that can declare it, from any higher-precedence level down (SPEC-API-41). `wire:ghost="actionName, other"` expression targeting now gates host activation to just the named actions, matching the SDD §10.1 grammar. `only`/`except` are enforced the same way, on every host-creation path (directive and attribute auto-attach alike) — not just resolved and transported.
- Selective silence is now overridable: a sync-only (property-write) or `wire:poll`-originated message still doesn't activate a ghost by default, but `#[Ghost(sync: true)]`/`#[Ghost(poll: true)]` now actually re-enables it (SPEC-API-20/21). `#[Renderless]` actions never activate a ghost, confirmed empirically on both Livewire lines via the real message/response shape each line exposes (SPEC-API-22).
- `php artisan ghost:inspect` (SPEC-API-42): lists every registered Livewire component with its fully-resolved config and, per field, which precedence level decided it (`class`, `inherited`, or `default` — SDD's config-file and package-default levels are deliberately reported as one `default` label, since a value matching the shipped default is indistinguishable at runtime from a value an app explicitly chose to leave unchanged once `config/ghostwire.php` is published), plus the detected Livewire line.
- Precedence and legacy/global-strategy validation suite: the class/inherited/config/default cascade (own class > inherited ancestor class > inherited trait > config > package default) and a "shared base `#[Ghost]`, zero `wire:ghost` in any view" scenario, both verified on Livewire 3.6 and 4.x.
- `#[Ghost(...)]` on an individual Livewire action method now actually reaches the runtime ([issue #9](https://github.com/matheusmarnt/ghostwire/issues/9) closed) — `ConfigResolver::resolve($class, $method)` already computed method-level overrides correctly (SPEC-API-10), but no production code path ever passed a method name, so the override had zero runtime effect. `GhostComponentHook` now additionally transports every action method's own declared `#[Ghost]` fields (`mode`/`delay`/`hold`/`rows`/`poll`/`sync`/`lazy` — `only`/`except` stay class-level-only) as a compact per-action map under a new `"a"` key in the `data-ghost` payload (e.g. `{"m":"synthesize","a":{"increment":{"m":"freeze"}}}`), validated client-side under the same closed-schema discard-on-any-violation policy as the rest of `data-ghost` (SPEC-SEC-02/03). The matching action's override is merged into the host's config for exactly the duration of the triggering Livewire commit, then restored; a directive-level `wire:ghost` modifier still outranks a method-level override, which in turn still outranks the class-level `#[Ghost]`.
- Animated skeleton bones: `shimmer` (default), `wave`, and `pulse` keyframes on a dedicated `.gw-bone::after` sheen overlay, selected purely by the existing `--ghostwire-animation` CSS custom property — no JS involved. All three touch only `transform`/`opacity` (SPEC-RND-05), so the sweep stays on the compositor thread. `--ghostwire-animation: none` (and `prefers-reduced-motion: reduce`) fall back to the sheen's own static, invisible `opacity: 0` (SPEC-RND-06).
- Automatic dark mode (FR-51): `--ghostwire-bone-color` and `--ghostwire-bone-highlight` both swap to dedicated `-dark` tokens under `prefers-color-scheme: dark` — OS/browser preference only, no manual toggle class.
- `aria-busy="true"` on every host while its ghost is visible, regardless of render mode (freeze/synthesize/keep/ignore) — cleared once settled (SPEC-A11Y-01). Reapplied after every Livewire morph, since Livewire's own attribute-diffing strips any attribute absent from the freshly-rendered server HTML — the same mechanism this package already had to work around once, for the `gw-frozen` class, in M1.
- Keyboard focus is now saved before a host is concealed and restored after, when (and only when) the ghosting genuinely displaced it (SPEC-A11Y-03) — `freeze` mode never needs this, since it only dims via opacity/pointer-events and never forces a browser blur.
- A single shared, page-wide `aria-live="polite"` region announces when ghosting starts and stops across all hosts combined — at most one "start" and one "end" announcement regardless of how many hosts are busy at once (SPEC-A11Y-04). Wording is overridable and the whole feature can be disabled via a `window.Ghostwire` JS global (`{ announcements: false }`, `{ messages: { busy, idle } }`) — deliberately not a `config/ghostwire.php` key, since this is a client-only concern.
- Optional CSP-nonce argument on `@ghostwireStyles($nonce)`/`@ghostwireScripts($nonce)` (SPEC-SEC-06) — omitted, both directives render exactly as before; passed, both tags carry a matching `nonce="..."` attribute, for apps enforcing a nonce-only Content-Security-Policy (no `'self'` host-source allowance).
- axe-core accessibility test suite (via `pestphp/pest-plugin-browser`'s built-in `assertNoAccessibilityIssues()`) covering the demo fixture and three gallery layouts, at rest and mid-ghost, plus behavioral browser tests for `aria-busy` timing and focus restoration — this milestone's accessibility Definition-of-Done gate.
- A real strict-CSP browser test (`script-src`/`style-src` limited to `'self'` plus a per-request nonce, no `'unsafe-inline'`/`'unsafe-eval'`) proving the gallery still fully functions — this milestone's CSP Definition-of-Done gate. Requires Livewire's own `csp_safe` config flag under a fully enforced policy (a Livewire/Alpine requirement, not something this package controls).
- The shared browser-test fixture page shell now declares `<title>`, `lang="en"`, one `<main>` landmark, and one `<h1>` — needed for axe-core's document-level rules to evaluate any route meaningfully; every fixture route now serves valid, landmark-complete HTML5 instead of a bare fragment.
- **v1.0 launch (M6):** public API surface frozen (SPEC-API-50, SPEC-PKG-11) — a snapshot test (PHP + JS) now fails CI the instant the `#[Ghost]` constructor signature, `config/ghostwire.php`'s key set, the CSS custom-property token set, or the `wire:ghost` modifier vocabulary changes shape without a deliberate, reviewed update.
- README fully rewritten (was still the M0 stub through M1-M5): real feature list, the Tier A/B/C compatibility matrix (FR-81/GOV-07), requirements table, GOV-05 badge block, and the official logo. Portuguese and Spanish translations added at `docs/readme-pt.md`/`docs/readme-es.md` (PRD §5.4).
- Public documentation/marketing site (`docs-site/`, Astro + Starlight, deployed to GitHub Pages via `.github/workflows/deploy-docs.yml`): a landing page with an interactive latency-comparison slider, an `/about` page, a `/gallery` page and a `/playground` page that both run Ghostwire's real, unmodified `js/src/synthesizer`/`renderer`/`registry` modules live in the browser against real DOM content (not a simulation), and ten `/docs/*` content pages (install, wire-ghost, ghost-attribute, choosing, compat, theming, how-it-works, security, testing, interop) including the FR-81 tier matrix and the FR-90..93 security/CSP/supply-chain/privacy posture, all reachable via Starlight's sidebar navigation.
- Local Bone Tree persistence (SPEC-LRN-01, SPEC-SEC-04): a learned tree is stored in `localStorage` under a versioned schema (`ghostwire.learned.v1`), one entry per component per viewport band (`xs`/`sm`/`md`/`lg`/`xl`/`2xl`, six bands at 0/640/768/1024/1280/1536px). Every read re-validates the envelope and clamps every geometry value; anything that doesn't match the expected shape or schema version is discarded silently rather than trusted, and the affected component simply learns again. The store is capped at a fixed 256 KB budget, with least-recently-used entries evicted first once it's full.
- `#[Ghost(lazy: true)]` (SPEC-LRN-02): for a component using Livewire's own lazy loading, paints a previously learned skeleton into the placeholder Livewire renders, before the component's real content ever loads. A component's own declared placeholder — a `placeholder()` method, a Livewire 4 `@placeholder` block, or an app-wide default placeholder — takes absolute precedence and is never touched (SPEC-LRN-05 / FR-56).
- `php artisan ghost:export` (SPEC-LRN-03, SPEC-SEC-05): turns a tree collected by `Ghostwire.exportLearned()` (a user-initiated browser download; no headless browser anywhere in this path) into a static Blade partial usable as a `@placeholder`/`placeholder()`. The downloaded JSON is re-validated server-side independently of the browser's own checks; the destination is resolved canonically and refused outside `resources/views`, refused outright when it's a symlink (live or dangling) or an existing directory regardless of `--force`, and otherwise requires `--force` to overwrite an existing file at that destination.
- Two new compact `data-ghost` keys, `g` and `n`, sent only for a request where learning is genuinely active (`learning.enabled`, `learning.store === 'local'`, non-production, and a component name matching `[a-z0-9.-]{1,64}`) — a client can never turn learning on for itself.
- Learning stays opt-in and non-production-only end to end (SPEC-LRN-04): `learning.enabled` defaults to `false`, and collection is additionally refused server-side whenever `app()->isProduction()`, regardless of what the config says.

### Removed

- **[Issue #4](https://github.com/matheusmarnt/ghostwire/issues/4) closed:** Laravel 11.x support dropped (12.x/13.x only going forward). Every Laravel 11.x release is covered by an active Composer security advisory; supporting it contradicts SPEC-SEC (FR-90 to FR-93), the security domain established in the PRD.
- `learning.quota_kb` removed from `config/ghostwire.php` (and from the frozen key set in `ApiSurfaceFreezeTest.php`). It was speculative config added in M0 for a learning store that only arrived in M7, and nothing ever read it — the local store's budget has always been a fixed 256 KB with LRU eviction, hardcoded in `js/src/index.js`. Nothing has been released, so no published version ever offered the key.

### Fixed

- Skeleton memoization was dead on arrival for any host with padding/border: the cache compared a border-box measurement against the `ResizeObserver`'s default content-box delivery, invalidating itself the instant it was set. The observer now requests `{ box: 'border-box' }` and reads the matching `borderBoxSize` field.
- `isAvatar()` misread a percentage `border-radius` (e.g. `"50%"`) as a pixel value, so any circular avatar larger than 100px rendered as a rounded rectangle instead of a circle.
- `repositionLayer()` re-read and re-applied the host's border-radius/overflow via `getComputedStyle` on every morph, even though neither can change between mount and unmount — this forced-style-recalc now happens once, in `mountLayer()`.
- A real table's colspan group-header row could be wrongly folded into the same repeat-sample run as its data rows, since the repeat signature matched on tag and class only — it now also considers direct-child count, so a structurally different row is never sampled alongside ones it doesn't resemble.
- `mountLayer()` read the host's computed style and bounding rect *after* appending the Ghost Layer to `document.body` — a forced synchronous reflow on every show cycle. Both reads now happen before the layer is created and appended; the layer's position/size styles are written onto it while it's still detached, so the append is the function's only DOM-tree write.
- The signature cache used to memoize a Bone Tree never accounted for a repeat run's real item count (only a fixed sampled-item shape), so a host whose repeated-item count changed (a filter, a shorter last page) kept serving a stale, wrong-count skeleton indefinitely — `ResizeObserver` only catches width changes, not count changes. The signature now includes the real count. The same cache also inherited the `SVGAnimatedString`-stringifies-identically bug already fixed once in the repeat-detection code (`className` → `getAttribute('class')`), fixed here too.
- `GhostComponentHook`'s `data-ghost` payload used to omit a field whenever it matched `ConfigResolver`'s *live*, `config()`-derived default — but the JS runtime's own fallback for an omitted field is a fixed literal. Any app publishing and customizing `config/ghostwire.php`'s `timing`/`silence`/`learning` keys would silently get the wrong value client-side for every omitted field. The omission decision now compares against a separate, genuinely fixed set of literals (`ConfigResolver::literalDefaults()`), matching what the JS runtime actually falls back to.
- The `component.init` auto-attach guard that's supposed to skip creating an attribute-driven host when `wire:ghost` is already present (SPEC-API-13) only checked the component root's own attributes — a component with `wire:ghost` placed on a descendant (not the root) still got a spurious extra host at the root, concealing the real one(s)' subtree. The guard now scans the whole component subtree, the same way the existing Livewire-3 poll-detection heuristic already does.
- Selective-silence and `#[Renderless]` detection could desync a host's pending-message count: a message correctly skipped in the show-decision (`onStart`) still ran its balancing `onPostPaint`/`onFinish` calls unconditionally, which could cancel or corrupt a genuinely concurrent, non-skipped message on the same host. All three handlers now agree on the same skip decision per message.
- `ConfigResolver` was never bound as a singleton, so its own ancestor/trait-chain cache never actually cached anything — every single Livewire component render on any app installing this package re-walked the full reflection chain from scratch.
- `aria-busy` and, separately, the pre-existing `.gw-concealed` concealment class were both silently stripped by Livewire's morph the instant a request landed mid-visible-window, for the identical reason `gw-frozen` once was (M1): Livewire's attribute-diffing removes any attribute the live node has that the freshly-rendered server node doesn't. Both are now reapplied in the existing post-morph hook, alongside the pre-existing `gw-frozen` reapply. Caught by the M5 final whole-branch review, not by any individual task's own scoped diff — cross-cutting by nature, exactly the class of bug this project's review process exists to catch.
- A host torn down while its ghost was still visible (e.g. inside a conditionally-rendered block) left the shared busy counter permanently above zero, silently disabling every future live-region announcement for the rest of the page's lifetime. `markBusy`/`clearBusy` are now idempotent per host, and both component-teardown paths call `clearBusy` unconditionally.
- Focus restoration used to steal focus back unconditionally after a ghost concealed a host — if the user had since moved focus elsewhere (e.g. into a `.gw-keep`-marked region), it would be yanked back regardless. It now only restores focus that was actually lost to the ghosting.
- The default `shimmer` animation's highlight sweep stayed at its light-mode near-white color in dark mode too, flashing over the dark bone color on every cycle; it now swaps to a dedicated dark highlight token.
- `card-grid`'s gallery fixture used an `<h3>` for its card titles directly under the new page-shell `<h1>`, skipping a heading level (axe `heading-order`) — demoted to `<h2>`.
- [Issue #6](https://github.com/matheusmarnt/ghostwire/issues/6): `onPostPaint` read every host's layout, then wrote its Ghost Layer position, in the same per-host loop iteration — with 2+ `wire:ghost` hosts on one component, this forced a synchronous reflow before every host after the first. All reads across a component's hosts now happen before any writes.
- [Issue #7](https://github.com/matheusmarnt/ghostwire/issues/7): the synthesizer's clip-filtering (SPEC-SYN-14) checked a candidate's clip visibility at the whole-entry level, then emitted every bone from that entry unfiltered — a multi-line text candidate straddling a scrollable ancestor's clip boundary could emit a bone actually outside the visible area. Bones are now individually re-checked against the same clip the repeat-sampling clone pass already enforced at bone granularity; the repeat-sampling template itself is deliberately left unfiltered (filtering it would silently drop entire cloned rows whenever the sampled instance itself was partially clipped).
- [Issue #4](https://github.com/matheusmarnt/ghostwire/issues/4) was attempted (pinning `laravel/framework` instead of `illuminate/support` in the CI matrix step) and reverted after real CI logs on this same PR showed it trades the original conflict for a worse one: `orchestra/testbench`'s Laravel-11-compatible branch only resolves to `laravel/framework` versions Composer's security-advisory policy blocks wholesale, so every Laravel 11.* cell failed regardless of PHP version. Remains genuinely open, same category as #2.
- CI: PHP 8.2 matrix cells now drop `pestphp/pest-plugin-browser` (no PHP-8.2-compatible release exists) and run only `tests/Unit`/`tests/Feature` — `tests/Contract` is excluded too, since its bridge-surface test calls Pest's own browser-only `visit()` helper, which silently exits the whole process successfully (a false green) once the browser plugin is absent ([issue #11](https://github.com/matheusmarnt/ghostwire/issues/11)).
- **M6:** `docs-site/astro.config.mjs`'s `base` was missing a trailing slash (`/ghostwire` instead of `/ghostwire/`) — `import.meta.env.BASE_URL` resolved without the trailing separator, so every hand-written `${base}xyz` link on the landing, about, gallery, and playground pages produced a malformed URL (e.g. `/ghostwiredocs/install/` instead of `/ghostwire/docs/install/`), breaking every internal nav link and the favicon site-wide. Caught via real-browser verification while building the gallery page, not by any automated check; fixed with a one-line config change.
- **M6:** the gallery and playground pages' synthesized `.gw-bone` elements initially rendered structurally correct but completely unstyled (no color, no shimmer) — neither page loaded Ghostwire's own `js/src/style.css`. Fixed by importing it directly on the gallery page (its bones live in the same document) and, on the playground page, by injecting the stylesheet's raw text into the live-preview iframe's own document on every repaint (its bones live inside that separate document/CSSOM, which a parent-page CSS import can never reach).
- **M6:** the playground page's inline `<script type="module">` prevented Astro from bundling its `js/src/*` imports at all (all resolved as 404s); removing the explicit `type="module"` attribute lets Astro's default script-processing bundle it correctly, as it already did for the gallery page.
- CI: [Issue #2](https://github.com/matheusmarnt/ghostwire/issues/2) closed — every `php` matrix cell failed instantly with `Could not read XML from file "--cache-result"`. The repo shipped no `phpunit.xml`/`phpunit.xml.dist`, so Pest's `Plugins\Configuration` generated a temporary config file at runtime inside an `assert()` call; CI's `shivammathur/setup-php` runs PHP's production ini (`zend.assertions=-1`), which compiles that `assert()` out entirely, so the file was never written. `realpath()` on the missing path then returned `false`, and Pest handed PHPUnit an empty `--configuration` value, which silently swallowed the following `--cache-result` flag. Fixed by shipping a real `phpunit.xml.dist` (mirroring Pest's own generated template), so the generate-and-`realpath()` branch never runs regardless of `zend.assertions` — also letting the now-redundant `--cache-directory=/tmp/pest-cache` CI workaround be dropped.
- `Tests\Browser\Security\CspTest` now runs the strict-CSP gallery fixture under the strictest policy each Livewire line actually supports, and asserts zero CSP violations on both lines with no exceptions: Livewire 4, with its opt-in `csp_safe` config flag enabled, needs no `'unsafe-eval'`; Livewire 3 is granted `'unsafe-eval'` because its stock Alpine evaluator cannot evaluate `wire:*` expressions at all without it — without that grant the gallery mounts no skeleton whatsoever (`__gwBoneCount` stays `0`), caught by CI. Ghostwire's own guarantee (SPEC-SEC-06: no `eval`, no `new Function` in the compiled bundle) is asserted statically against `resources/dist/ghostwire.js` in every matrix cell, including PHP 8.2 where the Browser suite doesn't run.
- **M7:** `Livewire::componentHook()` was registered from `GhostwireServiceProvider::boot()`; `ComponentHookRegistry` consumes the hook array exactly once, at the end of Livewire's own boot, so registering from `boot()` was silently dropped whenever Livewire's service provider booted first — an order package auto-discovery does not guarantee. Moved to `register()`. This affected the `data-ghost` transport shipped in M4.
- **M7:** `ghost:export` reported success even when `file_put_contents()` failed (an unwritable directory, a full disk) — the return value wasn't checked. Now checked, and reported as a failure.
- **M7:** `ghost:export` refused to overwrite an existing file without `--force`, but that check used `is_file()`, which is false for both a directory and a dangling symlink — so a dangling symlink at the destination bypassed both `--force` and the `resources/views` containment check. The destination is now refused outright whenever it's a symlink (live or dangling) or an existing directory, before any write is attempted.
- **M7:** `ghost:export`'s component-name gate used a PHP `$`-anchored regex without the `D` modifier, so — unlike the identically-written JavaScript-side check — it accepted a trailing newline (e.g. `"orders-table\n"`) and let it through into the exported filename. Fixed with PCRE's `D` (`PCRE_DOLLAR_ENDONLY`) modifier for parity.

### Scope (deferred, tracked for later milestones)

- A host that degrades from `synthesize` to `freeze` mid-cycle (rare — two consecutive slow syntheses, an unsupported CSS transform, or an empty host with no `.rows` hint) doesn't yet get its `gw-frozen` class reapplied after a morph the same way a `wire:ghost.freeze`/`#[Ghost(mode: 'freeze')]` host does. Found and deliberately deferred during the M5 final review: narrow blast radius (the dimmed/inert treatment can end slightly early; `aria-busy` and teardown are both unaffected), not yet filed as a tracked issue.
- `#[Ghost]` on a `class` (including inheritance from a base class or trait), the full directive⊕attribute precedence merge, selective silence overrides, `only`/`except` enforcement, and the hardened transport ship in M4 (SPEC-API-10..13, 20..23, 30..32, 40..42, SPEC-SEC-01..03). `#[Ghost]` on a `method` resolves correctly in isolation (unit-tested) but does not yet reach the runtime — the per-component-root transport has no path for per-action config; tracked as [issue #9](https://github.com/matheusmarnt/ghostwire/issues/9).
- The legacy/global-strategy validation suite proves the mechanism server-side (`data-ghost` present, correct payload, zero `wire:ghost` in the view) on both Livewire lines; a browser-level (actual rendered ghost behavior) counterpart for that same scenario is a nice-to-have follow-up, not yet written.
- Known, tracked, non-blocking gaps found during M3 (see GitHub issues #5, #6, #7): a renderer-side bone mount/render cost (~50-100ms) has no dedicated perf gate of its own; `onPostPaint` forces a reflow across multiple hosts on the same component (pre-existing since M1); the scrollable-clipping browser test and `emit()`'s own clip-filtering are each internally consistent today but not verified at the same granularity as each other.
- **M6, deferred (Minor, caught by task review, non-blocking):** the landing/about/gallery/playground pages have no `<!DOCTYPE html>` declaration (renders in quirks mode) and `index.astro`'s heading order skips from `<h1>` to `<h3>`; `/docs/ghost-attribute`'s "Precedence cascade" section says "Seven levels" but lists six (the real declarable-level count needs checking against `src/Support/ConfigResolver.php`, not guessed); the playground's Reset button doesn't call `registry.detach()` on the outgoing host before clearing it (a bounded, per-tab-session leak on a demo page, not a real-world concern).
